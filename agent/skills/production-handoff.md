# Production Handoff Standard (REBOOTv2)

Match the real package structure used in Daily Intelligence → Writing → Packaging → HOLD.

## Required package sections (psychology long-form)

When delivering a complete psychology package, use this order:

1. **Header** — title, content parent ID, DC run ID, lane, voice, visual system, publication status
2. **Source verification** — claims boundary, source IDs, what is NOT claimed
3. **Stable content metadata** — parent + LF / SH01–03 / essay / thumb / community IDs
4. **Title choices** — primary + alternates
5. **Long-form description**
6. **Keywords, tags, hashtags**
7. **Playlist placement** (recommended only; do not claim changes were made)
8. **Thumbnail concepts** — A/B with canvas, expression, text, color hierarchy, avoids
9. **Long-form architecture** — timed beats
10. **Full narration + illustrated scene plan** — sectioned with Hope direction, visual, on-screen words, narration
11. **Three complete Shorts** — narration, scenes, captions, bridge to long-form
12. **Companion essay** (when lane requires)
13. **Pinned comment question**
14. **Community draft** (status DRAFT ONLY)
15. **Production status** — writing / media / SRT / upload flags; YouTube ID null until real

## System Glitch short package

Minimum fields from the Day-1 ledger pattern:

- content_id, dc_run_id, source_candidate, lane
- first_title + alternates
- final_narration + word count (target 55–75 words / 25–35s)
- description, keywords, tags
- thumbnail specs A/B (palette locked: #09090B, #EF263D, #FF2DAA, #F5F5F5)
- scenes + captions
- claim links (e.g. S04, S05) and educational boundary
- statuses: script WRITING_COMPLETE | production NOT_STARTED | schedule HOLD | publication NOT_UPLOADED

## Hard boundaries

- Never invent YouTube video IDs, view counts, or “uploaded” status.
- Never claim a study proves universal gender/age ambition differences.
- Qualify enforcement actions as allegations until adjudicated.
- Research-only scans stop at recommendation — no script unless asked.
- Append-only ledger mindset: new events, do not erase prior status lines.

| Real step | Specialist |
